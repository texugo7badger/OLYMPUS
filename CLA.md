## 1. Why We Need a CLA

OLYMPUS is licensed under the [GNU Affero General Public License v3 or later](LICENSE)
("AGPL-3.0-or-later"). The AGPL is a strong copyleft license — it guarantees
that all users, including those who interact with OLYMPUS over a network,
receive the same freedoms you received when you first received the code.

The CLA serves three purposes:

1. **Protect OLYMPUS's license integrity** — Confirm you have the right to
   contribute your code under AGPL-3.0-or-later, and that your contribution
   does not infringe on anyone else's rights.

2. **Protect OLYMPUS's future** — Allow the Maintainer to enforce the AGPL
   (e.g., against bad actors who refuse to share their modifications)
   without first having to track down every individual contributor for
   permission.

3. **Protect users** — Make sure that every line of code in OLYMPUS has a
   clear, traceable provenance, so users can trust that what they're
   running is actually free software.

**This CLA does NOT take away your rights.** You retain full ownership of
your contributions. You keep your copyright. You can still use your own
code however you like — including in proprietary projects, since you
licensed it to the Project, not to anyone else.

**This CLA does NOT give the Maintainer the right to relicense OLYMPUS
under a non-AGPL license.** The Project is AGPL-3.0-or-later, permanently.
See Section 5 for the full relicensing guarantee.

restructuring guarantee (e.g., to dual-license under AGPL + Apache), the
Maintainer MUST obtain explicit written consent from every contributor
whose code is still in the Project. The Maintainer will use reasonable

git commits) and will publish a 90-day public comment period before any

## How to Sign

We use **[CLA Assistant 2.0](https://cla-assistant.io/)** to manage CLA
acceptance. The first time you open a pull request, CLA Assistant will
automatically post a comment asking you to accept this CLA.

**To sign:**

1. Open a pull request against the OLYMPUS repository.
2. CLA Assistant will post a comment with a link to accept the CLA.
3. Click the link, review this CLA, and click "Accept".
4. CLA Assistant updates the PR status check to "CLA signed".
5. Your PR is now eligible for review and merge.

**For employers / corporate contributors:**

If you are signing on behalf of your employer, CLA Assistant supports
corporate CLA acceptance — contact the Maintainer at
**texugo7badger@gmail.com** to set this up. The corporate signatory
will need to be a person authorized to bind the company to this CLA.

**Once signed, your acceptance applies to all current and future
contributions** to OLYMPUS. You do not need to sign again for future PRs.

## FAQ

### Q: Do I need to sign the CLA if I'm just fixing a typo?

A: Technically yes, but the Maintainer may waive the CLA requirement for
trivial contributions (typo fixes, formatting-only changes) at their
sole discretion. If you'd rather not sign the CLA for a one-line fix,
mention this in your PR and the Maintainer may either waive the CLA or
re-do the fix themselves.

### Q: What happens if I don't sign the CLA?

A: Your pull request cannot be merged. The Maintainer may still review
your changes and reimplement them from scratch (without using your
code), but your specific contribution will not be included.

### Q: I signed the CLA but my PR is still showing "CLA not signed".

A: This usually means you committed under a different email address than
the one associated with your GitHub account. Either:
- Add the email to your GitHub account (Settings → Emails), or
- Re-commit using your verified GitHub email.

CLA Assistant should detect the change within a few minutes.

### Q: Can I revoke my CLA acceptance?

A: No. Once you've signed, your acceptance is irrevocable — but it only
covers Contributions you've actually submitted. If you stop contributing,
no new Contributions are covered.

### Q: I want to contribute, but my employer hasn't approved this CLA. What should I do?

A: Tell your employer's legal team about this CLA. The Maintainer is
happy to provide:
- A one-page summary
- A redline comparison with the Apache CLA, GitLab CLA, Google CLA
- References to other companies whose employees have signed similar CLAs
- A direct call with your legal team to answer questions

Email **texugo7badger@gmail.com** to start the conversation.

### Q: Does this CLA let the Maintainer sell OLYMPUS to a company?

A: No. Section 5 (Relicensing Guarantee) explicitly forbids relicensing
OLYMPUS under a proprietary license. Even if the Maintainer sold the
Project, the buyer would be bound by the same guarantee — OLYMPUS stays
AGPL-3.0-or-later forever.

### Q: Does this CLA let the Maintainer make OLYMPUS closed-source?

A: No. Same reason — Section 5.

### Q: Does this CLA give the Maintainer exclusive rights to my code?

A: No. The license you grant is non-exclusive. You retain the right to
use your own code however you like, including in proprietary projects.
You're only licensing it to the Project under AGPL-3.0-or-later.

### Q: What if I want to contribute code that I've already published elsewhere?

A: You can — as long as you still own the copyright (i.e., you didn't
assign it to someone else). When you submit, mention the prior
publication in your PR description so the Maintainer can record the
provenance.

### Q: What if I want to contribute code from my employer's proprietary codebase?

A: **Don't.** That would be a copyright infringement and could expose
both you and the Project to legal liability. Only contribute code you
wrote yourself, or code that's already licensed under AGPL-compatible
terms.

### Q: Can I contribute code that I licensed under a permissive license (MIT, BSD, Apache-2.0)?

A: Yes — permissive licenses are AGPL-compatible. When you submit, note
the original license in your PR description so the Maintainer can record
it. The code will be re-licensed under AGPL-3.0-or-later when it's
merged into the Project (which is allowed by all permissive licenses).

### Q: Can I contribute code that's licensed under GPL-3.0?

A: Yes — GPL-3.0 is AGPL-3.0-compatible (AGPL is a stronger version of
GPL, so upgrading GPL → AGPL is allowed).

### Q: Can I contribute code that's licensed under GPL-2.0-only?

A: No — GPL-2.0-only is NOT AGPL-3.0-compatible. If you want to
contribute GPL-2.0 code, you'd need to also obtain permission from the
copyright holder to re-license under AGPL-3.0-or-later.
