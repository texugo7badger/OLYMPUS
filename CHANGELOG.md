## [v0.0.14] — 2026-10-24

**"THE HONEST LANE"** — the app was not broken by a bug; it was broken by five faults that multiplied. The GO plan's monthly quota was spent and nothing knew it, the walker threw away the provider's own error (it read `stderr`; v2 emits errors on `stdout`), five walkers ran the same hop at once, a Portuguese "planeje e execute" classified as `simple / no-planning` (so Apollo narrated instead of writing the plan), and the shell ran Turbopack in dev with `loading: () => null` on every panel (a blank pane looks like a dead dashboard). All five are fixed, with the evidence pinned in two new suites.

- **THE V2 ERROR TRUTH (`parseJsonEvents`)**: OpenCode v2 reports provider failures as STDOUT events — `{"type":"error","error":{"type":"provider.quota","message":"Go usage limit exceeded","retryAfterMs":392658000}}` — while `stderr` stays EMPTY and the process exits 1. The dispatcher built its message from `stderr` only, so five hops parked with the classless `error: "exit 1"`. The stream is now parsed first: the class, the provider's words and its `retryAfterMs` all survive, and an error event marks the run FAILED even at exit 0 (the `provider.no-route` + exit 0 specimen).
- **THE LANE FAILOVER (`src/lib/lane-health.ts`)**: a durable registry of what each model lane can do right now (alive / quota / no-route / rate-limit / auth), written by both the hop dispatcher AND the chat session, persisted at `~/.olympus/lane-health.json` so a restart does not re-learn a monthly cap the hard way. A LANE-DEAD class no longer retries inside the dispatcher (retrying a 4.5-day quota burns the whole crescendo budget) — the SAME hop re-posts on the next healthy lane for that god, the applied lane always first. Only when every lane is dead does the hop park, and it parks NAMING each lane and its cause.
- **THE CAMPAIGN LOCK (`src/lib/hop-runtime/walk-lock.ts`)**: five concurrent walks of hop `f0-1` in ninety seconds produced contradictory durations in the same second and a hop state rewritten by whoever finished last. One campaign per lane is now enforced on disk (atomic `wx` create, pid + boot id + heartbeat, steal-on-death, release never deletes a stolen-from lock). A second send answers "já existe uma campanha caminhando nesta lane" instead of forking a silent second walk.
- **THE PT-BR PLAN CLASSIFIER**: "Planeje e execute o desenvolvimento do AIME" became `complexity=simple, needsPlanning=false`, so the `[OLYMPUS-PLANNER]`/`[OLYMPUS-DESIGN]` markers were never injected and Apollo narrated. The Portuguese plan/build imperatives (planeje, desenvolva, implemente, construa, monte/crie/fazer + o projeto|app|sistema|site|dashboard) and the Portuguese architecture vocabulary are now architectural, with no over-trigger on short prompts.
- **THE LANE-AWARE POOL CAP (`maxHopsPerPoolFor`)**: the per-pool ceiling stays 2 for `nvidia-*` free pools (the #POOL-CONTENTION cure) but a paid/plan lane rides the full global cap — otherwise a single-lane strategy (every god on one OpenRouter lane) would be pinned to 2 concurrent hops for its whole life.
- **BYOK — `byok-deepseek`**: a new strategy family for the user's OWN paid key: all ten gods on DeepSeek V4.1 Flash v1017 (1M ctx / 393k out, $0.15/$0.60 per 1M). Deliberately NOT `custom-*` (hard-restricted to free models by the money-safety guard); mirrored in all four places `check-strategy-sync` verifies, and the guard now covers the prefix instead of silently skipping it. `apply-strategy` also records the strategy in `llm-providers.json`, so the LLM Strategy panel can never again show `free-hybrid` while the config runs `go-budget`.
- **THE RUN-STATE API (`/api/olympus/run-state`) + the StatusBar pill**: "is it working?" now answers from PROCESS evidence (walk lock pid + heartbeat, hop state on disk, lane health) instead of the 3-minute activity window that made a healthy 8-minute hop read as idle. RUNNING / PARKED / IDLE / UNVERIFIED, and a ⚠ when lanes are dead.
- **PRODUCTION BY DEFAULT**: the app ran `next dev` for the whole UAT because `isDev = !app.isPackaged`, so every dashboard click triggered an on-demand compile under load. A source run now serves the standalone build by default (`--dev` / `OLYMPUS_DEV=1` opt back in, a missing build degrades to dev, and a staleness check warns when the artifact predates the source tree).
- **VISIBLE PANEL LOADING**: all 27 dynamic panels used `loading: () => null`. `PanelLoading` renders a gold spinner + the panel name, so loading reads as loading and a failed chunk falls through to the error card instead of an empty rectangle.
- **GPU FALLBACK TTL**: the marker was forever, so one bad driver week left the Three.js brain rendering on the CPU ("OLYMPUS está bem travado"). It now expires after 7 days, `--reset-gpu` retries immediately, and the runtime no longer calls `disableHardwareAcceleration()` after ready (the errors.log specimen).
- **THE PREVIEW SPAWN ROOT**: the dev-server GATE validated a lane root (it read `package.json` there) while the manager spawned from the SLUG-derived path — a different, empty directory (the stale `aime-uploaded-files-aime` note home). The manager now accepts the gated root and wins with it.
- **Gates**: battery **61 PASS / 0 FAIL / 1 declared SKIP** (62 suites, incl. the new `lane-failover` 18 assertions and `walk-lock` 13), `tsc --noEmit` 0, electron `tsc` 0, `check-strategy-sync` 11/11.

- **Free strategies no longer load cost telemetry** — the free config shape dropped `./.opencode/olympus` (the overlay that writes `~/.olympus/metrics/cost.jsonl`), so the status bar / Cost menu showed no token usage during free sessions. The overlay is back in the free plugin set (now 4 plugins) and cost events flow again.
- **Context indicator always showed 0%** — OpenCode ≥1.18 stores sessions in SQLite (`~/.local/share/opencode/opencode.db`), but `/api/olympus/context-usage` only read legacy JSON session files that no longer exist. The route now reads real usage from the DB (keyed by `conversationId` → warm session, fallback: newest session), so the ctx % + "new session" button work again.
- **"Stop" / reset / new-session didn't actually stop the run** — the terminal's `stop()` only reset client state; the in-flight POST kept streaming for up to 10 minutes (the stuck "anchored summary" loop the user saw, which kept appending events even after reset). `submit()` now uses an AbortController; `stop()`, reset, and new-session abort it, which propagates to `req.signal` and cancels the server-side warm opencode POST.
- **Handoff summaries could poison the next session** — `buildConversationSummary` fed the last 8 messages verbatim; a run of repeated assistant output (e.g. the loop) was replayed into the new session. Consecutive assistant/system/delegation/todo entries now collapse to the last one.
